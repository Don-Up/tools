#### 1. 网络基础与 OSI 模型（Networking Basics & OSI Model）

#### 4. TCP / UDP 传输层（Transport Layer）

| 英文术语 | 核心含义 | 技术场景例句 |
| :--- | :--- | :--- |
| **TCP (Transmission Control Protocol)** | 传输控制协议（可靠的面向连接的协议） | *We use **TCP** for reliable data transmission.* |
| **UDP (User Datagram Protocol)** | 用户数据报协议（不可靠的无连接协议） | *We use **UDP** for low-latency applications.* |
| **Connection-Oriented** | 面向连接（需要建立连接） | *TCP is **connection-oriented**.* |

| **Reliable Transmission** | 可靠传输（保证数据到达） | *TCP provides **reliable transmission** with retransmission.* |

| **Three-Way Handshake** | 三次握手（建立 TCP 连接的过程） | *TCP uses a **three-way handshake** to establish a connection.* |

| **Window Size** | 窗口大小（允许发送但未确认的最大数据量） | *TCP uses **window size** for flow control.* |
| **Congestion Control** | 拥塞控制（避免网络过载） | *TCP uses **congestion control** to avoid network collapse.* |
| **Flow Control** | 流量控制（避免接收方过载） | *TCP uses **flow control** to match the receiver's speed.* |
| **Retransmission** | 重传（丢失数据包重新发送） | *TCP **retransmits** lost packets.* |
| **Timeout** | 超时（等待响应的最长时间） | *The connection **times out** if no response is received.* |
| **SACK (Selective Acknowledgment)** | 选择性确认 | *TCP supports **SACK** to improve retransmission efficiency.* |

### 深度拆解 + 避坑指南

#### 1. TCP vs UDP（核心区别）
| 特性 | **TCP** | **UDP** |
| :--- | :--- | :--- |
| **连接状态** | 面向连接（需三次握手） | 无连接 |
| **可靠性** | 可靠（有重传和确认） | 不可靠（无重传） |
| **顺序保证** | 保证数据顺序 | 不保证顺序 |
| **速度** | 较慢（有开销） | 较快 |
| **适用场景** | HTTP、SSH、数据库连接 | 视频流、VoIP、DNS |

- **技术场景**：*Use TCP for reliability-critical applications like HTTP and SSH. Use UDP for speed-critical applications like video streaming and gaming.*

#### 2. HTTP Methods（GET vs POST vs PUT vs PATCH vs DELETE）
| 方法 | 幂等性 | 安全性 | 用途 |
| :--- | :--- | :--- | :--- |
| **GET** | ✅ 是 | ✅ 安全（只读） | 获取资源 |
| **POST** | ❌ 否 | ❌ 不安全（修改状态） | 创建资源 |
| **PUT** | ✅ 是 | ❌ 不安全 | 全量更新资源 |
| **PATCH** | ❌ 否 | ❌ 不安全 | 部分更新资源 |
| **DELETE** | ✅ 是 | ❌ 不安全 | 删除资源 |

- **技术场景**：*Use GET for read operations, POST for creation, PUT for full updates, PATCH for partial updates, and DELETE for deletion. Only GET should be used for cacheable requests.*

#### 3. HTTP/1.1 vs HTTP/2 vs HTTP/3（演进对比）
| 特性 | **HTTP/1.1** | **HTTP/2** | **HTTP/3** |
| :--- | :--- | :--- | :--- |
| **连接复用** | 持久连接 | 多路复用 | 多路复用 |
| **头部压缩** | 无 | HPACK | QPACK |
| **服务器推送** | 不支持 | 支持 | 支持 |
| **底层协议** | TCP | TCP | QUIC (UDP) |
| **队头阻塞** | 有 | 有（TCP层） | 无 |

- **技术场景**：*HTTP/2 improves performance with multiplexing and header compression. HTTP/3 uses QUIC over UDP to eliminate head-of-line blocking.*


### 快速决策流（0.5 秒选择）

你在处理网络问题时——

- 选择传输协议？
  - 需要可靠性 → **TCP**
  - 需要低延迟 → **UDP**

- 选择 HTTP 方法？
  - 读取数据 → **GET**
  - 创建数据 → **POST**
  - 全量更新 → **PUT**
  - 部分更新 → **PATCH**
  - 删除数据 → **DELETE**

- 排查连接问题？
  - 测试连通性 → `ping`
  - 查看路由路径 → `traceroute`
  - 查看开放端口 → `netstat`
  - 测试 API → `curl`
  - DNS 解析 → `nslookup` / `dig`

- 处理 HTTP 状态码？
  - 成功 → **2xx**（200, 201）
  - 重定向 → **3xx**（301, 302）
  - 客户端错误 → **4xx**（400, 401, 403, 404, 429）
  - 服务端错误 → **5xx**（500, 502, 503, 504）
