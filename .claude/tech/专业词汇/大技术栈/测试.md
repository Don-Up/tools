### 软件测试相关专业高频词汇速查表

#### 1. 测试层级与类型（Testing Levels & Types）

| 英文术语 | 核心含义 | 技术场景例句 |
| :--- | :--- | :--- |
| **Unit Test** | 单元测试（测试单个函数/方法） | *We **write** **unit tests** for each public method.* |
| **Integration Test** | 集成测试（测试多个模块的协作） | *We **run** **integration tests** to **verify** the interaction between services.* |
| **Component Test** | 组件测试（测试一个完整组件） | *We **perform** **component tests** on the payment module.* |
| **End-to-End Test (E2E)** | 端到端测试（模拟真实用户场景） | *We **run** **E2E tests** to **validate** the entire user flow.* |
| **System Test** | 系统测试（测试完整系统） | *We **execute** **system tests** before each release.* |
| **Acceptance Test** | 验收测试（验证是否满足需求） | *We **run** **acceptance tests** to **ensure** the feature works as expected.* |
| **Regression Test** | 回归测试（确保新代码不破坏旧功能） | *We **run** **regression tests** after every change.* |
| **Smoke Test** | 冒烟测试（快速验证核心功能） | *We **run** **smoke tests** to **check** if the build is stable.* |
| **Sanity Test** | 健全性测试（快速验证修复是否生效） | *We **perform** a **sanity test** to **confirm** the fix works.* |
| **Performance Test** | 性能测试（测试系统响应速度） | *We **run** **performance tests** to **measure** response time.* |
| **Load Test** | 负载测试（测试系统在预期负载下的表现） | *We **run** **load tests** to **simulate** peak traffic.* |
| **Stress Test** | 压力测试（测试系统的极限） | *We **run** **stress tests** to **find** the breaking point.* |
| **Spike Test** | 尖峰测试（测试突发流量） | *We **run** **spike tests** to **check** if the system handles sudden traffic spikes.* |
| **Security Test** | 安全测试（检查安全漏洞） | *We **perform** **security tests** to **identify** vulnerabilities.* |
| **Usability Test** | 可用性测试（测试用户体验） | *We **conduct** **usability tests** with real users.* |
| **Exploratory Test** | 探索性测试（边学边测） | *We **perform** **exploratory testing** to **find** edge cases.* |
| **Manual Test** | 手动测试（人工执行） | *We **run** **manual tests** for scenarios that are hard to automate.* |
| **Automated Test** | 自动化测试（脚本自动执行） | *We **write** **automated tests** to **speed up** the feedback loop.* |

### 快速决策流（0.5 秒选择）

你在讨论测试相关时——

- 测试的**范围/层级**？
  - 单个函数/方法 → **Unit Test**
  - 多个模块协作 → **Integration Test**
  - 模拟用户操作 → **E2E Test**
  - 验证业务需求 → **Acceptance Test**

- 测试的**目的**？
  - 验证核心功能是否正常 → **Smoke Test**
  - 确保新代码不破坏旧功能 → **Regression Test**
  - 测试系统在极限下的表现 → **Stress Test**

- 测试的执行**方式**？
  - 自动化运行 → **Automated Test**
  - 人工手动操作 → **Manual Test**
  - 边学边测，自由探索 → **Exploratory Test**

- 测试的**替身类型**？
  - 模拟依赖对象 → **Mock**
  - 返回固定数据 → **Stub**
  - 记录函数调用 → **Spy**

- 测试的**质量指标**？
  - 代码覆盖比例 → **Code Coverage**
  - 检查测试有效性 → **Mutation Testing**

- 测试的**开发方法**？
  - 先写测试再写代码 → **TDD**
  - 用自然语言描述行为 → **BDD**


### 技术场景组合示例（完整的测试流程描述）

> *We follow **TDD** in our development workflow. First, we write a **unit test** that **asserts** the expected behavior. We **run** the test and see it **fail** (red). Then, we **implement** the simplest code to make it **pass** (green). For external dependencies, we **mock** the API calls using **Jest** to **isolate** the unit. We also **write** **integration tests** to **verify** the interaction between services. All tests are **automated** and **run** in the **CI/CD pipeline** on every PR. We aim for **80% code coverage** and **track** **flaky tests** separately. Before the release, we also **perform** **smoke tests** to **validate** the core flow, and **regression tests** to **ensure** no existing features are broken.*

> （我们在开发流程中遵循 **TDD**。首先，我们编写一个**单元测试**来**断言**预期行为。我们**运行**测试并看到它**失败**（红色）。然后，我们实现最简单的代码让它**通过**（绿色）。对于外部依赖，我们使用 **Jest** **模拟** API 调用，以**隔离**被测试单元。我们还**编写** **集成测试**来**验证**服务之间的交互。所有测试都是**自动化**的，并在每个 PR 的 **CI/CD 流水线**中**运行**。我们的目标是 **80% 的代码覆盖率**，并单独**跟踪** **不稳定的测试**。在发布之前，我们还**执行** **冒烟测试**来**验证**核心流程，以及**回归测试**来**确保**没有破坏现有功能。）
