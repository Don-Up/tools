### 快速决策流（0.5 秒选择）

你在刷题或讲解算法时——

- 选择数据结构？
  - 需要快速查找/去重 → **Hash Set / Hash Map**
  - 需要按顺序访问 → **Array / List**
  - 需要后进先出 → **Stack**
  - 需要先进先出 → **Queue**
  - 需要动态取最值 → **Heap / Priority Queue**

- 选择算法思路？
  - 问题可拆分成重叠子问题 → **DP (Memoization / Tabulation)**
  - 每次做局部最优选择 → **Greedy**
  - 需要探索所有路径 → **Backtracking + Pruning**
  - 有序数组中查找 → **Binary Search**

- 描述时间复杂度？
  - 用 **Big-O Notation**
  - 说 **Time Complexity** 和 **Space Complexity**

- 讨论题解质量？
  - 暴力解用 **Brute Force**
  - 最优解用 **Optimal Solution**
  - 需要说明取舍用 **Trade-off**（如时间换空间）


### 技术场景组合示例（面试时的标准回答）

> *My brute force solution would be to check every possible subarray, which gives us O(n²) time complexity and O(1) space. However, we can optimize this using a sliding window approach. We maintain two pointers, `left` and `right`, and expand the window while the condition holds. This reduces the time complexity to O(n). The key insight is to use a hash map to track the frequency of characters. We also need to handle the edge case where the input string is empty. This solution is optimal because we only traverse the array once.*

> （我最初的暴力解法是检查所有可能的子数组，时间复杂度为 O(n²)，空间复杂度为 O(1)。不过，我们可以用滑动窗口来优化。我们用两个指针，left 和 right，在条件满足时扩大窗口。这样能将时间复杂度降低到 O(n)。关键的技巧是使用哈希映射来跟踪字符的频率。我们还需要处理输入字符串为空这一边界情况。这个解法是最优的，因为我们只遍历了一次数组。）
