# 一、核心技巧

1. **简单**: 优先使用简单常用的，自己熟悉的词汇和表达方式，不一定要最合适的。
2. **短句**: 有时不能立即想出组织长句的方法，可以将其拆分为若干短句。
3. **省略**: 有时可以省略次要/多余部分，不是每个词都需要翻译出来，只要核心意思表达出来就行。
4. **转换**: 有时可以转换思维，而不是直译，意思相近就行。
5. **名词**: 有时可以优先使用"名词"，搭配介词来简化翻译。
6. **缺陷**: 允许表达瑕疵，不必追求完美。
7. **口译**: 在读完中文句子3秒内，即可输出英文句子。

# 二、名词修饰

## 公式
冠词/量词 + 前置定语 + 中心名词 + 后置定语 + 状语(方式→方位→时间)。
## 前置定语
### 类别
1. 形容词, 如useful
2. 组合形容词, 如open-source
3. 副词+形容词，如highly efficienct
### 形容词顺序
大致：限定词 → 评价形容词 → 特征 → 材质 / 来源。
> 例如: a useful open‑source high‑performance component

> 这个顺序按语感来一般不太会出错，即兴表达时顺序出错问题也不大。
## 后置定语
当先行词是**that/who/which**且主从句主语一致时，优先省略先行词并采用更简洁的方式:
1. 现在分词，表主动/正在。
2. 过去分词，表被动/完成。
3. 形容词后置(ed结尾)或形容词短语(如ideal for，used for等等)。
4. 优先使用介词并搭配"名词化"技巧: 
	1. for, 表目的，前面可以加特定动词，如used；或者用that/which平叙，例如object that creates ...，。
	2. from，表来源，前面可以加特定动词，例如inherited。
	3. with/including/without/excluding，表包含或伴随与否。
>注意: 只有**关系代词在从句充当主语，并且从句含有 be 动词 (am/is/are/was/were)**，才可以删掉「关系代词 + be」，并用剩下的部分做后置定语。例如: `the logic that handles timeout` 不能变成 `the logic handles timeout` 
### 补充1: 省略关系代词

1. 关系代词后接 **动词** → 优先用 **分词（-ing / -ed）**
    
2. 关系代词后接 **be动词 + 形容词** → 直接接 **形容词成分**
    

如果那个修饰成分是**“状态或特征”**（即包含系动词），**不要用 that is，直接用“同位语”或“逗号 + 形容词短语”**，这样能省掉一个动词，语速直接翻倍。

- ❌ 旧算法输出：This tool, **that is** very useful for debugging, is free.（多了一个that is，稍显啰嗦）
    
- ✅ 补丁后输出：This tool, **very useful for debugging**, is free.（直接把形容词短语扔进去，去掉that is，大脑负担骤减）
    

| 定语类型          | 修饰词性质       | 最优处理方式                         | 示例                                              |
| ------------- | ----------- | ------------------------------ | ----------------------------------------------- |
| **形容词/形容词短语** | 描述状态（系动词）   | **直接后置（省略 `that is`）**         | This tool, **useful for debugging**, is free. |
| **动词（主动）**    | 描述动作（实义动词）  | **现在分词（-ing）替代 `who/which`**   | The developer **excelling at** testing...     |
| **动词（被动）**    | 描述被动作（被动语态） | **过去分词（-ed）替代 `who/which is`** | The branch **rejected** due to...             |
### 补充2: **定语从句**省略关系代词可能会出问题

例如: The developer **excels** at automated test scripts **is** on leave today.

|解法|结构|示例|适用场景|
|---|---|---|---|
|**解法A（定语从句）**|主干 + **who** + 从句|The developer **who excels at** writing automated test scripts is on leave today.|最稳妥，符合你算法第3.1条（牵涉到动词，用 who）|
|**解法B（现在分词）**|主干 + **现在分词短语**（主动含义）|The developer **excelling at** writing automated test scripts is on leave today.|更简洁，等同于 `who excels at`，分词作后置定语|
|**解法C（介词短语，若可能）**|主干 + **with + 名词**|The developer **with expertise in** automated testing is on leave today.|把“擅长”转化为名词 `expertise`，使用你的第3.2条（介词+名词化）|

### 补充3: 介词使用技巧

1. 表目的用for
    
2. 表包含用with
    
3. 表不包含用without或with no
    
4. 表范围/时间用in, on, within
    
5. 表位置用inside, outside, above, behind等
    
6. 表方位用where或in(或其它介词) which
    
7. 表抽象定义用where
    
8. 表原因用why
    
9. 表因果用due to/because of/owing to
    
10. 表手段用by, via, with和through
    

### 补充4: 悬垂分词错误

That feature branch rejected due to failing the code review was finally merged into the main branch after **fixing concurrent conflicts**.

> 这个 `-ing` 动作(fixing)的执行者，不是句子的**主语**(feature branch)

| 解法            | 结构                          | 示例                                                                    | 适用场景             |
| ------------- | --------------------------- | --------------------------------------------------------------------- | ---------------- |
| **解法A（状语从句）** | 主干 + **after + 完整从句（含主语）**  | ...was merged after **we fixed** the concurrency conflicts.           | 最稳妥，逻辑清晰         |
| **解法B（被动分词）** | 主干 + **after being + 过去分词** | ...was merged after **being fixed** for concurrency conflicts.        | 强调“分支被修复”，不关心谁修的 |
| **解法C（独立主格）** | 主干 + **with + 名词 + 过去分词**   | ...was merged into main, **with the concurrency conflicts resolved**. | 最书面化，技术文档最爱      |
## 状语
状语相对于后置定语，所描述的往往是更"宏观"的信息，因此都放到句末。
即兴表达时优先按以下顺序来:
1. 方式状语(by/with/using/through/via等)
2. 方位状语(in/on/inside/outside等)
3. 时间状语(when/during/before/after等)
### 中文中的状语代表词
1. 在...
2. 从...
3. 当...
4. ...中/里
5. ...以来(since)
# 三、缺乏主语时如何处理

| 处理方式                              | 核心公式                               | 语体 / 使用场景                                     | 技术/文档场景示例                                                                         |
| :-------------------------------- | :--------------------------------- | :-------------------------------------------- | :-------------------------------------------------------------------------------- |
| **1. 被动语态**                       | `It is + 过去分词` 或 `名词 + is + 过去分词`  | **极正式/书面**，常见于技术文档、错误信息、系统提示。**强调动作，不强调执行者**。 | *The data **is stored** in Redis.* <br> （数据被存储在 Redis 中。）                         |
| **2. 虚拟主语 (It)**                  | `It is + 形容词/名词 + to do / that...` | **中性/通用**，常用于说明“做某事是...的”。                    | ***It** is recommended to use HTTPS in production.* <br> （建议在生产环境中使用 HTTPS。）      |
| **3. 真实主语 (We / You)**            | `We/You + 动词原形`                    | **口语/非正式**，常见于团队内部沟通、代码注释、教程（You）。            | ***We** need to restart the service.* <br> （我们需要重启服务。）                            |
| **4. 泛指主语 (Someone / Something)** | `Someone / Something + 动词原形`       | **口语/泛指**，常用于描述“有人做某事”或“出了某事”。                | ***Someone** should review this PR before merging.* <br> （合并前，应该有人 review 这个 PR。） |


### 深度拆解 + 避坑指南

#### 1. 被动语态：最安全的选择（技术文档首选）
- **公式**：`主语 + be + 过去分词 (+ by 执行者，可省略)`
- **优点**：最客观、最严谨。非常适合写 README、API 文档或错误提示。
- **技术场景**：
  > *The configuration file **is loaded** at startup.*
  > （配置文件在启动时被加载。）

#### 2. 虚拟主语 (It)：表达“推荐/必要/可能”
- **公式**：`It is + 形容词 (recommended / necessary / important) + to do...` 或 `It + 动词 (seems / appears) + that...`
- **场景**：用于提出要求、建议或陈述一般事实。比被动语态更符合“人性化”的表达。
- **技术场景**：
  > ***It** is necessary to validate the input before processing.*
  > （在处理之前，有必要验证输入。）

#### 3. 真实主语 (We / You)：最自然的团队沟通
- **公式**：`We/You + 动词 + 宾语`
- **优点**：语气亲切，像是“我们一起做”，适合 Slack、邮件、Code Review。
- **避坑**：
  - 在正式的 Release Notes 中，避免频繁使用 `I`，多用 `We`（代表团队）。
  - `You` 在文档中通常指“用户”或“开发者”，如 *You should set the timeout to 30s.*
- **技术场景**：
  > ***We** should deploy this to staging first.*
  > （我们应该先把这个部署到 staging 环境。）

#### 4. 泛指 (Someone / Something)：当“人不重要，事重要”时
- **公式**：`Someone / Something + 动词 + 宾语`
- **场景**：描述“有某个未知因素”或“某个特定的人需要做某事”。
- **技术场景**：
  > ***Something** went wrong with the build process.*
  > （构建过程中出了点问题。）


### 快速决策流（0.5 秒选择）

你要表达“缺乏主语”的句子？

- 写正式文档、API 说明，强调**“客观事实”**？
  - 用 **被动语态**（最安全）
  - 例：The file is uploaded.

- 想表达**“建议/必要性”**，但不想太生硬？
  - 用 **It is + adj + to do**
  - 例：It is essential to test this.

- 日常团队沟通、邮件，**“我们一起做”**？
  - 用 **We**
  - 例：We need to fix this now.

- 写给用户的指南、教程，**“你应该”**？
  - 用 **You**
  - 例：You can find the log in `/var/log`.

- 描述“有人做了某事”或“出了故障”，**人不重要**？
  - 用 **Someone / Something**
  - 例：Something is blocking the port.
