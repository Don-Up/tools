以下是为每种主语缺失处理方式提供的五组中英对照例句（英文放在中文下方的引用块中）：

---

### 1. 被动语态 (It is + 过去分词 / 名词 + is + 过去分词)

**中文例句：**  
1. 该配置文件需在部署前修改。  
2. 所有日志默认保存在 `/var/log` 目录下。  
3. 这个漏洞已在最新补丁中被修复。  
4. 测试用例每夜自动执行。  
5. 用户密码必须加密存储。

> **English:**  
> 1. The configuration file must be modified before deployment.  
> 2. All logs are saved in the `/var/log` directory by default.  
> 3. This vulnerability has been fixed in the latest patch.  
> 4. Test cases are automatically executed every night.  
> 5. User passwords must be stored in encrypted form.

---

### 2. 虚拟主语 (It is + 形容词/名词 + to do / that...)

**中文例句：**  
1. 定期备份数据库至关重要。  
2. 建议在提交前运行单元测试。  
3. 启用双因素认证是安全的做法。  
4. 奇怪的是，这个错误只在生产环境出现。  
5. 值得注意的是，该算法的时间复杂度为 O(n log n)。

> **English:**  
> 1. It is crucial to back up the database regularly.  
> 2. It is recommended to run unit tests before committing.  
> 3. It is a safe practice to enable two-factor authentication.  
> 4. It is strange that this error only occurs in the production environment.  
> 5. It is worth noting that the algorithm has a time complexity of O(n log n).

---

### 3. 真实主语 (We / You + 动词原形)

**中文例句：**  
1. 我们可以通过增加缓存来提升响应速度。  
2. 你需要在 `settings.py` 中配置数据库连接。  
3. 我们在发布前应该先做一次压力测试。  
4. 你可以用这条命令查看容器日志。  
5. 我们决定把前端迁移到 React 框架。

> **English:**  
> 1. We can improve response time by adding more cache.  
> 2. You need to configure the database connection in `settings.py`.  
> 3. We should run a stress test before the release.  
> 4. You can use this command to view container logs.  
> 5. We decided to migrate the frontend to the React framework.

---

### 4. 泛指主语 (Someone / Something + 动词原形)

**中文例句：**  
1. 有人在生产环境误删了数据表。  
2. 昨晚某个定时任务触发了意外的报警。  
3. 有人建议改用 gRPC 代替 RESTful API。  
4. 这个接口在高峰期出了超时问题。  
5. 有人把测试环境的密钥泄露到了代码仓库。

> **English:**  
> 1. Someone accidentally dropped a data table in the production environment.  
> 2. Something triggered an unexpected alert from a scheduled job last night.  
> 3. Someone suggested switching to gRPC instead of RESTful APIs.  
> 4. Something caused timeout issues on this endpoint during peak hours.  
> 5. Someone leaked the test environment credentials into the code repository.
