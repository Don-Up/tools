# choices.html 选择题文本生成

`choices.html` 本身只做一件事：把一段**纯文本**解析成多选题卡片。
所以出题的全部功夫都在「把文本写对」上——格式不对不会报错，只会静默丢题、丢选项、丢解析。

## 1. 标准样例

```
The quick brown fox jumps over the lazy dog.
1. A cat
2. A dog
3. A bird
4. A horse
2: 只有 A dog 语法正确。

Which one is correct?
1. True
2. False
1
```

- 第 1 行：题目文本（题干）。
- 接下来若干行：选项，格式 `序号. 内容`。
- 最后一行：答案行，`N` 或 `N: 解析`。
- 一个块 = 一道题；块与块之间不需要任何标记。
- 题干里带 `snippet` 两个字时，页面会自动弹出代码窗（配合 `------` 分隔线用）。

## 2. 逐行规则

| 行的样子 | 页面怎么认 | 备注 |
|---|---|---|
| 普通文字 | 题干 | 每块的第一行。题干若以数字开头，页面不再自动加 `1. ` 前缀 |
| `1. 内容` | 选项 | 正则 `^(\d+)\.\s*(.+)$`。序号可以不是 1 开头，但答案行要写对应的序号 |
| `2` | 答案 | 单独一个数字，等价于 `2` + 无解析 |
| `2: 解析文字` | 答案 + 解析 | 冒号后必须有一个空格 |
| `---` | 忽略 | 整行丢弃，用来做视觉分隔随意 |
| `# 注释` | 注释 | 只在「答案行之后 / 新题干之前」或「块的第一行」安全；写在选项中间会被当成无效选项丢掉 |
| `------` | 代码分隔线 | 分隔线之后**必须空一行**，再写代码；分隔线之后的全部内容都当作代码 |

## 3. 三条硬性限制

1. **答案行只能有一位数字。** 带解析时页面取 `lines[i][0]`，也就是答案行的**第一个字符**。
   - 写 `10: 解析` → 答案被读成 `1`。
   - 结论：一道题最多 9 个选项，答案行写 `1`~`9`。
2. **`------` 后必须空一行。** 代码片段取的是 `separateIndex + 2` 开始的行，
   分隔线本身占 1 行，所以分隔线和代码之间要空 1 行；少空一行，最上面那行代码会被吃掉。
3. **每个选项都必须写 `序号. 内容`。** 不符合 `^(\d+)\.\s*(.+)$` 的行会被静默丢弃；
   一个块的选项全被丢光时，这个块整个不显示。

其他容易踩的点：

- 答案行的数字指的是**你文本里写的序号**，不是洗牌后的位置。页面会把选项随机打乱，
  再把正确答案重新编号，所以选项顺序随便写，只要序号和答案行对得上。
- 没写解析时，解析面板显示 `no explanation`。

## 4. 影响朗读的写法

页面把文本交给 Web Speech 朗读前会先做一遍清洗：

- 去掉 ``() # * < > ` • __`` 这些符号（所以这些符号只是排版，不会被念出来）。
- `e.g.,` → `such-as`。
- `/` → 空格。
- `—` → `, `。
- 句末的 `? ! ; , .` 后面跟空格 → 换行（用来切句停顿）。
- 选项内容末尾会自动补 `. `（已经是句号就不补）。

因此：

- 选项写成 `True` / `False` 开头时，`play()` 直接 return，**这一项永远不会被念**。
  想让它出声就别用 True/False 开头。
- 题干里出现 `snippet` 会自动弹出代码窗，注意这是按**字面子串**匹配的，
  题目里恰好有这七个字母就会被触发。
- 想让某段文字不被念，用 `()` 包起来会被删掉（但也会从屏幕上消失）。

## 5. 常见写错 → 现象 → 正确写法

| 写错 | 现象 | 正确写法 |
|---|---|---|
| 选项写成 `- 内容` | 该选项消失 | `1. 内容` |
| 答案写成 `10` | 找不到 / 判错 | 题干最多 9 个选项，答案写 `1`~`9` |
| 答案写成 `2:解析`（冒号后没空格） | 解析第一个字被吃掉 | `2: 解析` |
| `------` 后直接写代码 | 第一行代码不见了 | `------` 后空一行再写代码 |
| 选项中间插 `# 注释` | 注释行被丢（没事） | 注释写在答案行之后 |
| 块之间用 `---` | 无影响，自动忽略 | 可以用 |
| 题干以数字开头 | 页面不再加编号 | 题干别以数字开头，或自己带上编号 |

## 6. 批量生成（JSON → 文本）

一个题库 JSON 生成一段可粘贴文本的脚本模板：

```js
// gen-choices.mjs  用法: node gen-choices.mjs bank.json > questions.txt
import { readFileSync } from 'node:fs'

const bank = JSON.parse(readFileSync(process.argv[2], 'utf8'))
const lines = []

for (const q of bank) {
  lines.push(q.question)                       // 题干
  q.options.forEach((opt, i) => {              // 选项
    lines.push(`${i + 1}. ${opt.text}`)
  })
  const n = q.options.findIndex(o => o.correct) + 1
  if (n < 1) throw new Error(`选项没标正确项: ${q.question}`)
  if (q.explanation) lines.push(`${n}: ${q.explanation}`)  // 答案 + 解析
  else lines.push(String(n))                              // 只要答案
  lines.push('')                                          // 空行分隔, 解析时会被过滤
}

if (bank.code) {                            // 可选的代码片段
  lines.push('------')
  lines.push('')
  lines.push(...bank.code.split('\n'))
}

console.log(lines.join('\n'))
```

输入 JSON：

```json
[
  {
    "question": "Which sentence is grammatically correct?",
    "options": [
      { "text": "He go to school", "correct": false },
      { "text": "He goes to school", "correct": true },
      { "text": "He gone to school", "correct": false }
    ],
    "explanation": "主语是第三人称单数,一般现在时动词加 s。"
  }
]
```

## 7. 自检清单

粘贴之前对一遍：

- [ ] 每个选项都是 `序号. 内容`？
- [ ] 答案行是单个数字（1~9），带解析时冒号后有空格？
- [ ] 答案数字在文本里真实存在对应的选项序号？
- [ ] `------` 后面空了一行？
- [ ] 题干里没有意外的 `snippet`（除非就是要弹代码窗）？
- [ ] 选项没有以 `True` / `False` 开头（除非就是不打算念它）？

## 8. 页面拿到文本之后

1. `buildMultipleChoiceComponents(rawText)` 解析 → 每题一张卡片，选项随机打乱后重新编号。
2. 原文整段存进 `localStorage.rawText`，刷新页面会自动重建。
3. 题干含 `snippet` → 代码窗弹出，代码内容来自 `------` 之后的片段。
4. `play` / `play q` / `loop` 朗读，朗读前按第 4 节清洗文本。
5. `play q` 读的是「题干 + 全部选项」，`play` 读单个选项；带解析的题目会显示解析面板。
