### 深度拆解 + 避坑指南

#### 1. `dependencies` vs `devDependencies` vs `peerDependencies`
| 依赖类型 | 安装时机 | 适用场景 |
| :--- | :--- | :--- |
| **dependencies** | 生产环境 | 运行时必需的包（如 `react`, `axios`） |
| **devDependencies** | 开发环境 | 仅开发时需要的包（如 `eslint`, `jest`, `webpack`） |
| **peerDependencies** | 由宿主提供 | 插件/库需要但期望宿主安装的包（如 `react`, `vue`） |

- **技术场景**：*Put runtime packages in `dependencies`, build tools in `devDependencies`, and framework packages in `peerDependencies`.*

#### 2. `Webpack` vs `Vite`（构建工具的选择）
| 特性 | **Webpack** | **Vite** |
| :--- | :--- | :--- |
| **启动速度** | 慢（需要打包所有模块） | 快（利用 ESM 按需加载） |
| **热更新** | 慢（需要重新打包） | 快（只更新修改的模块） |
| **配置复杂度** | 高（需要大量配置） | 低（开箱即用） |
| **插件生态** | 非常丰富 | 快速增长中 |
| **适用场景** | 大型复杂应用 | 中小型应用、快速迭代 |

- **技术场景**：*Use Webpack for large, complex applications with extensive customization. Use Vite for smaller projects where development speed is critical.*

#### 3. `Tree Shaking` 的工作原理
| 概念 | 说明 |
| :--- | :--- |
| **ES Module** | 树摇只对 ESM 有效（`import`/`export`），对 CommonJS 无效 |
| **Side Effects** | 在 `package.json` 中标记 `"sideEffects": false` 以允许树摇 |
| **Dead Code** | 未使用的代码在打包时被移除 |

- **技术场景**：*To enable tree shaking, use ES modules and set `"sideEffects": false` in package.json.*


### 快速决策流（0.5 秒选择）

你在进行前端工程化建设时——

- **选择打包工具**？
  - 大型复杂应用 → **Webpack**
  - 中小型应用、快速迭代 → **Vite**
  - 库开发 → **Rollup**
  - 极速构建 → **esbuild**

- **管理依赖版本**？
  - 允许次版本更新 → **`^1.2.3`**
  - 仅允许补丁更新 → **`~1.2.3`**
  - 锁定精确版本 → **`1.2.3`**

- **保证代码质量**？
  - 代码检查 → **ESLint**（JS/TS）+ **Stylelint**（CSS）
  - 代码格式化 → **Prettier**
  - 提交前检查 → **Husky + lint-staged**
  - 提交信息规范 → **Conventional Commits**

- **配置多环境**？
  - 通用配置 → `.env`
  - 开发环境 → `.env.development`
  - 生产环境 → `.env.production`
  - 本地覆盖 → `.env.local`

- **实施 CI/CD**？
  - GitHub 仓库 → **GitHub Actions**
  - GitLab 仓库 → **GitLab CI**
  - 自建服务 → **Jenkins** 或 **GitHub Actions self-hosted runner**

- **监控线上应用**？
  - 性能监控 → **APM**（如 Datadog、New Relic）
  - 错误追踪 → **Sentry**
  - 日志采集 → **结构化日志 + ELK / Loki**
  - 健康检查 → **/health 端点 + 监控告警**


### 技术场景组合示例

> *Our frontend project uses Vite as the bundler for fast development and build times. Dependencies are managed with pnpm in a monorepo with multiple workspaces. We use ESLint and Prettier for code quality, enforced by Husky pre-commit hooks. The CI pipeline runs on GitHub Actions, which triggers linting, unit tests, and a build on every push. The build artifact is deployed to the staging environment first, then to production using blue-green deployment. We use feature flags to control feature rollout and Sentry for error tracking. The bundle size is optimized with code splitting and tree shaking, and we use cache busting with content hashes to ensure users always get the latest version.*
