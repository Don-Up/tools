### 快速决策流（0.5 秒选择）

你在讨论数据库相关内容时——

- 想优化查询速度？
  - 用 **Index** / **Query Optimization** / **Execution Plan**
  - 避免 **Full Table Scan** / **Slow Query**

- 处理并发与事务？
  - 用 **Transaction** / **ACID** / **Isolation Level**
  - 避免 **Deadlock** / **Dirty Read**
  - 选择 **Pessimistic Lock** 或 **Optimistic Lock**

- 扩展数据容量？
  - 同库拆表用 **Partitioning**
  - 跨库拆数据用 **Sharding**

- 平衡冗余与性能？
  - 用 **Normalization**（减少冗余，适合写入）
  - 用 **Denormalization**（增加冗余，加速读取）

- 处理 Schema 变更？
  - 用 **Migration** / **Rollback**
  - 测试数据用 **Seeding**

> *We identified a **slow query** in the order service. The **execution plan** showed a **full table scan** on the `orders` table. We **created** a **composite index** on `(user_id, created_at)` to **accelerate** the query. Additionally, we **partitioned** the table by `created_at` to **reduce** the index size. > （我们在订单服务中发现了一个**慢查询**。**执行计划**显示对 `orders` 表进行了**全表扫描**。我们在 `(user_id, created_at)` 上**创建**了一个**复合索引**来**加速**查询。此外，我们按 `created_at` **分区**了该表，以**减小**索引大小。我们还**配置**了**只读副本**，将报表查询**卸载**到副本上。对于写密集型操作，我们将**隔离级别**设置为 `READ COMMITTED`，以**避免**不必要的锁。所有更改都**包装**在带有适当**回滚**处理的**事务**中。）
