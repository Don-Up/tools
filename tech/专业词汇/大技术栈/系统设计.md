### 系统设计相关专业高频词汇速查表

#### 1. 架构风格与拓扑（Architecture Styles & Topology）

| 英文术语 | 核心含义 | 技术场景例句 |
| :--- | :--- | :--- |
| **Monolithic** | 单体架构（所有功能打包在一起） | *We're **migrating** from a **monolithic** architecture to microservices.* |
| **Microservices** | 微服务（独立部署的小型服务） | ***Microservices** **improve** team autonomy and deployment velocity.* |
| **Serverless** | 无服务器（FaaS，按需运行） | *We use **serverless** functions for sporadic background jobs.* |
| **Event-Driven** | 事件驱动的（响应事件而非请求） | *The **event-driven** architecture **decouples** the producer and consumer.* |
| **Layered Architecture** | 分层架构（如 Controller-Service-Repository） | *We follow a **layered architecture** to separate concerns.* |
| **Hexagonal Architecture** | 六边形架构（端口-适配器模式） | ***Hexagonal architecture** makes the core logic independent of external frameworks.* |
| **SOA (Service-Oriented)** | 面向服务的架构（ESB 集成） | *We're **moving away** from **SOA** towards microservices.* |

#### 3. 数据流转与处理模式（Data Flow & Processing Patterns）

| 英文术语 | 核心含义 | 技术场景例句 |
| :--- | :--- | :--- |
| **Sync / Synchronous** | 同步（请求-响应阻塞） | ***Synchronous** calls **block** the thread until the response arrives.* |
| **Async / Asynchronous** | 异步（非阻塞回调/消息） | *We **switched** to **asynchronous** communication for better scalability.* |
| **Request-Response** | 请求-响应模式（REST/gRPC） | *Most read operations follow the **request-response** pattern.* |
| **Pub-Sub (Publish-Subscribe)** | 发布-订阅模式（一对多广播） | *We use a **pub-sub** model to **broadcast** events to multiple consumers.* |
| **Polling** | 轮询（定期拉取） | *The consumer **polls** the queue for new messages.* |
| **Webhook** | Webhook（事件回调） | *We **expose** a **webhook** for third-party integrations.* |
| **Streaming** | 流式（实时数据管道） | *We **process** clickstream data via **streaming** pipelines.* |
| **Batch** | 批处理（定时大批量） | *Nightly reports are generated via **batch** jobs.* |
| **ETL (Extract-Transform-Load)** | 数据抽取转换加载 | *We **run** an **ETL** pipeline to sync data to the warehouse.* |
| **Idempotent** | 幂等的（重复执行结果相同） | *The payment handler must be **idempotent** to **avoid** double charges.* |

| 英文术语 | 核心含义 | 技术场景例句 |

### 深度拆解 + 避坑指南

#### 1. Scalability vs Performance（容易混淆的两个词）
| 术语 | 定义 | 技术场景 |
| :--- | :--- | :--- |
| **Scalability** | 系统在增加资源后，性能能随资源增加而**线性提升**的能力。 | *Does this design **scale** to 10 million users?* |
| **Performance** | 系统的**当前**响应速度/吞吐量。 | *The **performance** is good at 100 rps.* |

**区别**：Performance 是“现在有多快”，Scalability 是“以后加机器还能有多快”。

#### 2. Consistency vs Availability（分布式系统 CAP 定理的两难）
| 术语 | 定义 | 决策时刻 |
| :--- | :--- | :--- |
| **Consistency** | 所有节点在同一时间看到相同的数据。 | 强一致（CP 系统）通常牺牲可用性。 |
| **Availability** | 每个请求都能收到响应（即使数据不是最新的）。 | 高可用（AP 系统）通常牺牲一致性。 |

- **技术场景**：*We chose **eventual consistency** for the user activity feed to **ensure** **high availability**.*
- **解释**：活动流允许短时间不一致，换取系统永远不挂。

#### 3. Resilience vs Fault Tolerance（恢复 vs 零中断）
| 术语 | 定义 | 实现手段 |
| :--- | :--- | :--- |
| **Fault Tolerance** | 系统能**无缝继续运行**，用户完全无感知。 | 冗余实例、主备切换。 |
| **Resilience** | 系统**会出问题，但能快速恢复**，用户可能感知到几秒延迟。 | 重试、超时、熔断、降级。 |

- **技术场景**：*We use circuit breakers to **improve resilience** without building full **fault tolerance**.*
- **解释**：完全无感知的容错成本极高，大多数系统只需要“快速恢复”的韧性。


### 快速决策流（0.5 秒选择）

你在做系统设计决策时——

- 考虑**服务之间如何通信**？
  - 同步用 **Request-Response / gRPC / REST**
  - 异步用 **Pub-Sub / Message Queue / Event-Driven**

- 考虑**数据如何流转**？
  - 实时用 **Streaming**
  - 定时大批量用 **Batch**
  - 导入数仓用 **ETL**

- 考虑**如何应对故障**？
  - 瞬间切换用 **Fault Tolerance**
  - 快速恢复用 **Resilience**（含 **Retry / Circuit Breaker / Timeout**）

- 考虑**如何扩展**？
  - 加机器用 **Horizontal Scaling**
  - 升配置用 **Vertical Scaling**

- 考虑**数据一致性与可用性的权衡**？
  - 强一致用 **Consistency**
  - 允许短暂不一致用 **Eventual Consistency**


### 技术场景组合示例（完整的系统设计描述）

> *We're designing a **high-availability** order processing system. The **API Gateway** receives requests and routes them to the **order service**. For scalability, the service is **stateless** and can **scale horizontally**. We use a **message queue** to **decouple** the order service from the **payment service**, allowing **async** processing. To handle failures, we **implement** **retries** with **exponential backoff** and a **circuit breaker** to **prevent** cascading failures. The order data is stored in a PostgreSQL database with **read replicas** for **read scalability**. The **RPO** is set to 5 minutes and the **RTO** to 30 minutes.*

> （我们正在设计一个**高可用**的订单处理系统。**API 网关**接收请求并将其路由到**订单服务**。为了可扩展性，该服务是**无状态**的，可以**水平扩展**。我们使用**消息队列**来**解耦**订单服务和**支付服务**，实现**异步**处理。为了应对故障，我们**实现了**带有**指数退避**的**重试**机制，以及**熔断器**来**防止**级联故障。订单数据存储在 PostgreSQL 数据库中，配有**只读副本**以实现**读扩展**。**RPO** 设置为 5 分钟，**RTO** 设置为 30 分钟。）
